# MINER 로컬 진단 패키지 v1.0.0

우선 확인 대상: **macOS / WARP 2026.8.2100.0 / MINER 1.2.2**. Windows도 같은 형식으로 비교합니다. 이 도구는 MINER나 WARP를 설치·업데이트·복구하거나 게임을 실행하지 않습니다. 기존 1.2.2 앱을 그대로 둔 상태에서 사용합니다.

## 실행

Mac은 칩에 맞는 ZIP을 풀고 `시작.command`를 엽니다. Windows는 ZIP을 풀고 `MINER-Diagnostics.exe`를 엽니다. Python이나 관리자 권한은 필요하지 않습니다. Mac은 ad-hoc 서명, Windows는 미서명입니다. Apple 공증·Microsoft 게시자 인증을 받은 도구가 아닙니다. 차단되면 출처와 제공된 SHA-256을 확인한 뒤 해당 파일에 대한 OS 실행 허용을 사용하세요. Gatekeeper나 보안 제품 전체를 끄지 마세요.

Mac의 터미널에서 실행할 수도 있습니다. 아래 경로는 ZIP을 푼 실제 위치로 바꾸세요.

```bash
"/실제/압축푼폴더/MINER-Diagnostics" --interactive
```

실행 허용이 어려우면 저장소 소스와 Python 3.10 이상으로 같은 도구를 실행할 수 있습니다.

```bash
python3 v5/diagnostics/collect.py --interactive
```

## 재현 순서

**같은 진단 창을 계속 사용**합니다. 각 단계가 저장됐다는 안내를 확인한 뒤 다음 단계로 넘어가세요. 단계 기록 중에는 WARP 설정을 바꾸지 마세요.

1. MINER를 시작하기 전 `1`을 입력합니다. 이미 문제가 생긴 상태라면 우선 `6`부터 기록해도 됩니다.
2. 평소처럼 MINER를 연결한 뒤 `2`를 입력합니다.
3. 가능하면 연습 모드에서 재현하고 게임 중 `3`을 입력합니다. 진단 도구는 최소화해 두어도 됩니다.
4. 통계창이 멈추거나 클라이언트로 돌아온 시점에 `4`를 입력합니다.
5. MINER에서 중지를 누르고 완료 또는 오류가 표시되면 `5`를 입력합니다. 게임 중 강제로 WARP를 전환하지 마세요.
6. 오류가 발생한 시점에는 `6`을 추가 입력하고 VAN 번호 등 **오류 코드만** 입력합니다. `0`으로 저장·종료합니다.

각 단계마다 바탕화면의 **같은 MINER-Diagnostics-날짜-난수.zip**을 원자적으로 갱신합니다. Ctrl+C/창 종료 전까지 저장된 단계는 유지됩니다. 내용 확인 후 개발자에게 직접 전달하세요. 자동 전송하지 않습니다. 시각·단계·OS 버전도 공유 정보임을 확인하세요.

## 수집과 개인정보

WARP 버전·모드·상태·전송 방식, SOCKS5 응답, 기본/참조 게임 IP/가상 주소 경로의 인터페이스 비교, DNS 종류, 시스템 프록시/PAC 사용 여부, MINER 관련 프로세스 수·메모리, CPU 관측값, 설정의 포트·MTU, 복구 기록·캐시 존재와 크기·수정 시각, 최근 로그의 오류 종류별 건수와 VAN 코드만 기록합니다. 읽을 수 없는 root 소유 파일은 `permission_denied`로 남깁니다. 진단을 위해 sudo를 요구하지 않습니다.

**원본 로그, 패킷, 계정, 토큰, SSID, 사용자 이름, IP 주소 값, 브라우징 기록은 내보내지 않습니다.** 주소·인터페이스의 식별값은 실행마다 새 키로 만든 HMAC이며 같은 실행 안에서만 비교 가능합니다. 원본 로그를 모두 익명화했다고 가정하는 대신, 허용된 항목만 추출합니다. ZIP에는 `report.json`, `SUMMARY.txt`가 들어갑니다. 원본 파일을 지우지 않습니다.

기본값은 로컬 검사와 로컬 SOCKS 인사만 수행합니다. 실제 DNS/TLS 요청이 필요하면 별도 실행 옵션을 사용합니다.

```bash
"/실제/압축푼폴더/MINER-Diagnostics" --interactive --active
```

`--active`는 고정된 Cloudflare/Riot/LoL 호스트에만 DNS·인증서 검증 HTTPS 요청을 보냅니다. WARP trace는 프록시의 원격 DNS를 사용하며 직접 연결로 재시도하지 않습니다. 일반 HTTPS는 OS 경로를 사용하고 환경변수 HTTP 프록시는 사용하지 않습니다. 사설 CA가 필요한 네트워크는 TLS 실패로 남을 수 있습니다. 각 외부 검사는 별도 자식 프로세스에서 7초 제한을 둡니다. DNS/TLS가 성공해도 UDP 게임 핑·장시간 안정성·로그인·Vanguard 호환성을 입증하지 않습니다.

## 기록 해석

- **실행 중 WarpProxy:** 예상 상태입니다. Local Proxy는 모든 앱의 트래픽을 자동 전달하지 않습니다. MINER의 DNS·선택 TUN이 함께 준비돼야 지정 Riot TCP가 전달됩니다.
- **MASQUE와 UDP:** MASQUE 전송 프로토콜과 Traffic and DNS 모드는 별개입니다. WarpProxy에서도 MASQUE가 UDP를 사용할 수 있습니다. `Mode: Warp`만 보고 MASQUE 프로토콜이 확인됐다고 판단하지 않습니다.
- **중지 후 WarpProxy:** 복귀 미완료 후보입니다. 앱 오류와 해당 시점 상태를 함께 확인해야 합니다.
- **중지 후 MINER DNS:** 복구 미완료 후보입니다. 다른 어댑터·VPN·수동 DNS를 임의 초기화하지 않습니다.
- **다른 기본 경로/시스템 프록시:** 다른 VPN·PAC 등 충돌 가능성입니다. 사용자가 의도한 설정일 수 있으며 자동으로 끄지 않습니다.
- **Vanguard:** macOS용 LoL과 Windows용 Vanguard는 구성이 다릅니다. Mac의 일반 네트워크 오류를 Vanguard 오류로 분류하지 않습니다. Windows에서는 실제 VAN 코드·서비스 상태를 함께 확인합니다. 서비스나 안티치트를 끄거나 우회하지 않습니다.

`104.160.131.3`은 **고정 참조 주소**이며 실제 접속 중인 게임 서버를 알아냈다는 의미가 아닙니다. 실제 UDP 목적지·RTT·손실률·MTU 문제는 별도 동의하에 목적과 범위를 정한 후 검증해야 합니다. 개인정보 때문에 이 도구는 게임 연결 목록이나 패킷을 덤프하지 않습니다.

CPU 값은 Mac의 ps 평균 비율과 Windows의 누적 CPU 초로 지표가 다릅니다. 게임 프레임이나 순간 부하를 직접 측정한 값이 아니며 플랫폼 사이 수치를 그대로 비교하지 않습니다. 반복 기록 시 같은 기기 안에서만 참고하세요.
