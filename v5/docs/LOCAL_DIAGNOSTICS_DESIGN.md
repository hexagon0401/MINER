# 1.2.2 로컬 안정성 진단과 다음 설계

## 확인된 사실과 아직 확인되지 않은 원인

사용자 보고: macOS, WARP 2026.8.2100.0, MINER 1.2.2. Local Proxy 복귀 실패, 클라이언트/게임 네트워크 오류와 끊김. Windows에서도 유사 보고가 있습니다. 사용자 장비에서 수집된 결과·오류 원문은 아직 없습니다. 원격 Linux의 모의 시험을 실제 학교망 재현으로 표현하지 않습니다.

코드에서 재현한 결함: `warp.restore()`는 `Connected`이면서 모드가 아직 `WarpProxy`인 중간 상태를 즉시 실패로 판단했습니다. CLI 상태가 비동기로 반영되는 경우를 회귀 테스트로 재현하고, 제한 시간 내 두 조건을 함께 확인하도록 고쳤습니다. 이미 `Warp`+Connected 상태면 복귀 재시도로 연결을 끊지 않습니다. **이 변경은 진단 브랜치의 소스 수정이며 설치된 1.2.2 앱이나 이번 독립 진단 도구가 자동 적용하지 않습니다.** 정식 앱은 별도 네이티브 패키징·설치·복구 검증 후 배포해야 합니다.

Local Proxy는 SOCKS TCP 경로를 제공하는 앱 접근 모드이고 MASQUE는 WARP의 터널 전송 방식입니다. Traffic and DNS의 `Warp` 모드 확인과 MASQUE/UDP 프로토콜 확인은 분리합니다. GUI 문구를 근거로 전송 방식의 성공을 임의 표시하지 않습니다.

## 단계별 증거와 판단

한 진단 실행 안에서 before → connected → in_game → post_game → after_stop을 기록합니다. 오류는 별도 error 단계로 추가합니다. 자동 재현을 위해 게임을 실행하거나 게임 도중 WARP를 전환하지 않습니다. 기본 검사는 로컬 관측, 명시적 `--active`는 고정 호스트 DNS·OS HTTPS·SOCKS 원격 DNS HTTPS 비교입니다. SOCKS 경로 실패 시 직접 재시도하지 않습니다.

| 관측 | 가능한 원인 | 다음 검증/조치 |
|---|---|---|
| WarpProxy인데 SOCKS 인사 실패 | 로컬 포트/데몬/포트 설정 불일치 | CLI 포트와 프로필 비교, WARP 버전·상태 확인. 다른 프로세스를 임의 종료하지 않음 |
| SOCKS TLS 성공, 같은 호스트 OS TLS 실패 | 선택 TUN·DNS·가상 주소 캐시·다른 프록시 | 기본/가상 경로와 DNS, PAC 상태를 비교. 전체 기본 경로를 추가하지 않음 |
| SOCKS TLS도 실패 | WARP 전송·TLS 신뢰·학교망 정책·서비스 응답 | 인증서 실패/timeout 등 오류 종류와 시각 비교. TLS 검증을 끄지 않음 |
| 중지 후 WarpProxy 잔류 | 명령 실패·비동기 상태·관리 정책/지원 CLI 차이 | 복귀 오류와 동일 시점 CLI 모드 확인. 중간 상태 재현 테스트 적용 |
| 중지 후 임시 DNS 잔류 | DNS 복구 실패·서비스 변경·권한 | 기존 복구 기록을 보존하고 해당 어댑터만 복구. 전체 네트워크 초기화 금지 |
| 기본 경로도 tunnel | 다른 VPN 또는 WARP full tunnel 공존 | 사용자가 의도한 설정인지 확인. 게임 중 자동 전환 금지 |
| 프록시/일반 HTTPS 정상인데 게임 끊김 | 실제 UDP 경로·손실·Wi-Fi·MTU·서버·클라이언트 오류 | 실제 오류 코드와 시각, 별도 동의한 제한적 UDP/RTT 검증 필요. 웹 요청 시간을 게임 핑이라 부르지 않음 |
| Mac의 'Vanguard' 보고 | 다른 네트워크/게임 오류일 가능성 | 오류 원문 확인. Windows Vanguard 코드로 가정하지 않음 |

보안 제품·안티치트 서비스는 읽기만 합니다. 끄거나 우회하지 않습니다. Windows vgc 서비스가 실행 중이라는 사실도 Vanguard 호환성 성공을 의미하지 않습니다.

## 다음 접근: 더 큰 터널보다 변경 범위를 줄이는 설계

1. **복귀를 트랜잭션으로 관리:** 명령 성공과 검증 성공을 분리하고 마지막 단계·오류를 구조화해 기록합니다. DNS 복구 → 엔진 종료 → 명시적 WARP 복귀 순서를 지킵니다. 클라이언트·게임 경계에서 모드를 바꾸지 않습니다. 실패 상태에서 '복귀 완료'를 표시하지 않습니다.
2. **정책을 자동 추측하지 않음:** 진단 결과로 현재 프로필의 차이와 권장 설정을 먼저 제시합니다. 사용자가 중지 상태에서 적용하고 다시 비교합니다. 인터넷 전체의 DNS·프록시·방화벽을 재설정하는 '자동 최적화'를 만들지 않습니다.
3. **가상 주소/실제 게임 UDP 경계 검증:** 직접 UDP 예외도 호스트 이름을 다시 해석해야 한다면 원래 학교 DNS의 차단 응답에 영향을 받을 수 있습니다. 이는 아직 가설입니다. 실제 게임 목적지/해석 경로 확인 후에만, Riot의 필요한 이름에 한정된 TLS DNS와 직접 UDP 경로의 분리를 시험합니다. 모든 게임 주소를 프록시로 보내거나 MTU를 임의 낮추지 않습니다.
4. **클라이언트 자체 프록시 지원을 우선 조사:** 지원되는 명시적 프록시가 있으면 TUN·시스템 DNS 변경을 줄일 수 있습니다. Riot 클라이언트에 공식 지원이 확인되지 않은 Chromium 플래그/환경변수를 해결책으로 단정하지 않습니다.
5. **운영체제별 장기 대안:** macOS Network Extension/앱별 VPN은 Apple entitlement·서명·배포/관리 조건과 지원 범위를 먼저 확인해야 합니다. Windows의 프로세스별 WFP 경로는 드라이버 서명·호환성·복구 설계가 필요합니다. 프레임워크만 교체해 학교망 또는 Vanguard 문제를 해결했다고 볼 수 없습니다. 유지비·권한·안정성 검증 전 현재 엔진을 무조건 대체하지 않습니다.

## 완료·배포 조건

이번 결과물은 Python 설치가 필요 없는 독립 진단 ZIP 3종과 소스, 개인정보·시간 제한·기본 무변경 테스트입니다. 정식 MINER·Homebrew의 최신 앱을 바꾸지 않는 별도 프리릴리스로 제공합니다. 사용자 보고 ZIP을 받은 후 후보 원인별로 재현 테스트를 추가하고, 실제 Mac/Windows에서 복귀·장시간 세션·통계창을 확인한 뒤 다음 앱 업데이트를 진행합니다. 모든 학교 차단·무선 손실·서버/안티치트 정책을 한 번에 해결하는 방법을 보장하지 않습니다.
